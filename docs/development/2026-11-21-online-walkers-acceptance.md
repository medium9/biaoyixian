## 手工复验步骤

1. 主机执行 `pnpm build`、`pnpm start`，保留终端服务；确认主机局域网IP及端口可被另一设备访问。
2. 两台同局域网设备打开 `http://主机IP:4173/`，各自创建不同昵称；确认在线人数和双方人物可见。主机使用 `localhost` 时仍连接同一进程，但该地址的本机存档与主机IP地址相互独立。
3. 一方出发并行走，另一方点选其人物，确认昵称、虚拟位置、累计有效时间和里程更新。
4. 行走方刷新，确认保存数值保留并出现“继续上次行走”；另一方只保留同一人物。关闭行走方页面，确认对方的角色和无成员详情移除。
5. 临时断开行走方到在线接口的连接，保持页面可见，确认断线提示及本机里程/时间增长；恢复连接后确认自动加入并更新进度。
6. 打开 `/?mode=demo`，确认显示19位模拟山友且真人房间没有新增该演示会话。
7. 重启 Node服务，确认在线列表重新建立、个人存档保留。若验证自定义端口，设置 `HOST`/`PORT` 后让两台设备同步改用新地址。

自动化生产定向验收可重复运行（先构建）：

```powershell
pnpm build
$env:E2E_PRODUCTION = '1'
pnpm test:e2e tests/e2e/online-walkers.spec.ts
Remove-Item Env:E2E_PRODUCTION
```

配置自行启动 `pnpm start`，绑定 `127.0.0.1:4178`，不复用其他服务；默认回归使用 `127.0.0.1:5173` 开发服务。所有浏览器测试使用一个worker，减少同一房间的测试干扰。

## 交付边界

在线信息保存在单进程内存中，100位身份容量、7.5秒租期及客户端上报方式不等同于生产规模/长期运行认证。人物位置与24.57km里程属于虚拟示意，不是GPS。浏览器本机进度不提供云端备份或跨设备迁移。每个浏览器应使用单个标签页行走，多标签页同时操作的一致性不在支持范围。本轮验收记录仅描述实际执行证据，历史版本的长时测试不代表新增在线服务已经完成同等压力测试。
