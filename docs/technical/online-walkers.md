# V1.7 真人同行技术说明

日期：2026-11-21。覆盖历史架构中“没有业务后端或真实同步服务”的限制；地图仍是本地SVG，个人进度仍为本机存档。需求见 [V1.7](../product/云走标毅线_需求变更记录_V1.7.md)。

## 模块与数据流

| 文件 | 职责 |
|---|---|
| `src/composables/use-presence.ts` | 本机在线令牌、轮询、连接状态、远端插值和离开通知 |
| `server/presence.mjs` | 同源 `POST /api/presence`、输入校验、租期、容量及房间快照 |
| `server/index.mjs` | Node HTTP入口，同时托管 `dist` 与在线接口 |
| `vite.config.ts` | 将同一房间中间件挂载到开发服务 |
| `src/pages/MapPage.vue` | 默认真人/显式演示分流、自己与远端人物合并、状态文案 |
| `src/composables/use-simulation.ts` | 本机行走与存档、演示人物、对在线人物的超越检测 |
| `src/components/map/MapCanvas.vue`、`src/components/walkers/WalkerInfo.vue` | 在线角色绘制、点选与详情来源标识 |

真人模式仅从种子数据初始化自己的角色，其他人物来自房间快照；演示模式初始化自己和19位模拟山友，并禁用在线轮询。个人移动在浏览器计算，服务端只保存最近一次上报的临时状态。

## 在线协议

`POST /api/presence` 使用 JSON 请求体，普通心跳包含：

| 字段 | 含义 |
|---|---|
| `token` | 浏览器生成的64位十六进制随机令牌，本机键 `yunzou.presence.v1` |
| `connection` | 每次页面加入生成的32位十六进制连接标识 |
| `routeId`、`routeVersion` | 必须与服务端导入的示意路线一致 |
| `player` | `nickname`、`mode`、`progressM`、`elapsedSeconds`、`moving` |

响应为 `{ players: [...] }`，仅含其他在线身份的公开字段：`id`、`nickname`、`mode`、`progressM`、`elapsedSeconds`、`moving`、`source: 'online'`。公开ID由令牌的 SHA-256 截断结果生成，响应不包含令牌、连接标识或本机身份ID。

退出请求使用同一信封并设 `leave: true`。服务端只有在连接标识匹配时才删除对应人物，避免旧页面延迟到达的退出通知删除刷新后的新连接。同来源多标签页共享令牌，多个标签页上报会相互覆盖，不提供跨标签页协同控制或一致性保证。支持范围是每个浏览器单个标签页行走及正常刷新；双人验证必须使用独立浏览器会话或设备。

请求体上限2048字节；只接受 JSON POST。若请求携带 `Origin`，必须与请求主机匹配。昵称限制为2～12个字符且无控制字符；步调限制为 `run`、`hike`、`stroll`；里程必须在0～24570范围，时间为非负有限数且不超过 `Number.MAX_SAFE_INTEGER`，移动标记为布尔值。到达终点强制为未移动。

接口错误包括400（请求或字段无效）、403（来源不匹配）、405（方法不支持）、415（内容类型不支持）和429（房间已满）。响应禁止缓存。随机令牌用于区分浏览器身份，不构成账号认证；服务器不验证客户端移动速度或运动真实性。

## 轮询与生命周期

- 正常请求结束后800毫秒再发下一次，单次请求超时为3200毫秒；没有个人资料时每250毫秒等待一次，不上报虚构身份。
- 成功快照将连接状态设为在线，远端位置和时间用500毫秒插值平滑；不会由本地行走引擎替在线山友推进。
- 请求失败后清空远端列表并约1500毫秒后重试；429时显示满员并约2000毫秒后重试。本机行走与持久化循环独立运行。
- 页面隐藏仍可维持连接，但上报 `moving: false`；个人行走引擎暂停隐藏期间计时并清除惯性。
- `pagehide` 或组件卸载取消轮询、正在执行的请求和插值，通过 `sendBeacon` 尝试退出；`pageshow` 自动重新加入。退出通知未送达时依赖租期。

服务端每个身份租期为7500毫秒，接受新请求时清理过期成员。连接正常的观察者在下一次轮询得到清理后的快照，所以掉线人物的消失时间还包含轮询与网络延迟。房间容量为100位身份（包含自己），达到容量后新身份需等待空位，已有身份可继续续约。

## 存储与重启

昵称在 `yunzou.profile.v1`；进度键保持 `yunzou.walk.v1:<profileId>:<routeId>:<routeVersion>`，继续保存模式、距离、有效时间、开始状态、控制方式、声音设置和已到访地标。在线令牌单独保存，不替代个人存档。上述存储按浏览器来源隔离，更换主机名/IP、协议或端口不会自动迁移数据。

服务端只有 `Map` 内存房间，没有数据库、在线历史或账号资料表。重启后旧房间消失，仍打开的浏览器在后续轮询重新加入；个人记录由本机继续提供。每个 Node 进程拥有各自独立房间，多进程/多实例不会共享在线列表。

## 运行部署

`pnpm build` 先执行类型检查再生成 `dist`；`pnpm start` 运行 `server/index.mjs`。缺少 `dist/index.html` 会报错并退出。默认 `HOST=0.0.0.0`、`PORT=4173`；Node版本至少22.12，生产服务直接依赖 `data/routes/schematic/biaoyixian-v1.json`。

同一进程托管网页和相对地址 `/api/presence`，无需独立配置API地址。静态内容支持 GET/HEAD，`/assets/` 资源使用长期缓存，其他静态内容要求重新验证。必须将 `dist/`、`server/`、路线JSON一起提供给 Node运行，不能用纯静态站点代替在线服务。

局域网设备访问主机IP及同一端口；`localhost` 指设备自身。默认 `pnpm dev` 仅监听 `127.0.0.1`，其房间与另启的生产 Node 服务相互独立。本轮不执行外网发布、Git推送或生产部署。

## 可重复的浏览器验证

默认 `pnpm test:e2e` 对 `127.0.0.1:5173` 的开发服务执行。设置 `E2E_PRODUCTION=1` 后，Playwright自行运行 `pnpm start`，使用 `HOST=127.0.0.1`、`PORT=4178`，不复用已有服务，因此需先运行 `pnpm build`。配置使用一个worker，避免测试间污染同一个房间。

PowerShell定向验收命令见 [README](../../README.md)。该生产自动化使用本机独立浏览器会话，不代替两台实体设备的局域网连通性验证。
