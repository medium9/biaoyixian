# V1.7 真人同行

日期：2026-11-21。接续本地 `main` 中尚未提交的真人同图实现，完成验证、修复和文档归档。本版在 [V1.6](云走标毅线_需求变更记录_V1.6.md) 的底部操控与示意地图上增加真人在线状态，保留原始 PRD 和历史版本。

## 入口与身份

- 默认 `/` 为真人同行模式，不自动填充模拟山友。没有其他用户时，地图上只有自己并提示等待同行者。
- `/?mode=demo` 为独立演示模式，展示自己与19位模拟山友，不加入在线房间。
- 首次输入2～12字昵称创建本机身份，无需密码。入口明确告知在线山友可看到昵称、虚拟位置、累计行走时间和里程。
- 昵称身份和个人行走记录继续保存在当前浏览器 `localStorage`，不增加账号、数据库或跨设备存档。每个浏览器使用单个标签页行走；多标签页同时修改同一进度不在本轮支持范围。不同设备分别创建身份。

## 同行行为

- 访问同一个 Node 服务的用户进入同一路线房间。创建昵称后即可互相看见，未出发者位于其当前保存位置并保持静止。
- 地图同步他人的昵称、虚拟路线位置、步调、累计有效时间、虚拟里程及移动状态；可点选查看人物信息，并标明“在线山友”。橙色人物仍代表自己。
- 保留自动/点击行进、跑山/徒步/慢走、到达与超越反馈，以及 V1.6 的底部控制、缩放、定位和聚合交互。
- 刷新后恢复同一份本机记录且不会重复增加自己的在线角色，仍需点击“继续上次行走”才继续移动；关闭或隐藏期间不补算时间。
- 同步断开时清除过期的远端显示并提示“连接断开 · 可继续行走”，本机行走和保存可继续；连接恢复后自动重新加入并分享当前进度。
- 离开页面时主动退出；非正常断开靠7.5秒租期过期清理。最多100位在线身份，满员者显示“路线已满 · 等待空位”并重试。

## 运行与范围

运行方式为 `pnpm build` 后 `pnpm start`，网页和在线接口由同一个 Node 服务提供。默认监听 `0.0.0.0:4173`，可通过 `HOST`、`PORT` 覆盖。两台设备同局域网访问主机IP的同一端口即可验证；`localhost` 只用于当前设备。

在线列表为单进程内存数据，服务重启后清空，仍打开的页面自动重新加入。本机进度不受服务重启影响。生产运行必须带 Node 服务，单独上传 `dist` 不能提供真人同行。本轮不发布、不推送。

路线、24.57km里程和人物位置均为虚拟示意，不读取或分享真实GPS。在线数据由浏览器上报，不是权威运动记录、实名身份或运动成绩认证。本版不包含聊天、好友、排行榜、跨服务器同步或长期在线历史。

## 验收口径

1. 两个独立浏览器会话在默认入口互相看见昵称和当前位置，移动后对方的时间、里程、位置同步变化。
2. 刷新保留本机行走数值和暂停恢复状态，对方只看到一个角色；关闭后从对方视图移除。
3. 同步故障时本地时间和里程仍增加并保存，恢复后无需手动加入即可同步。
4. 演示入口仍有19位模拟山友且不向真人房间发送状态。
5. 核心测试、类型检查/构建、浏览器全量回归以及生产 Node 启动和接口检查按实际结果记录；自动化双会话与两台实体设备实测分别标注。
